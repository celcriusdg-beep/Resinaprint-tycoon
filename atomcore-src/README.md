# ATOMCORE – 3D Nuclear Power Plant Tycoon

Build, operate and grow a nuclear power company in 3D: start with a pilot reactor, research
better designs, balance heat, steam, cooling and grid capacity, sign energy contracts, expand
to four sites and eventually build a fusion plant.

- **Play:** the production build lives in [`../atomcore/`](../atomcore/) (served at `/atomcore/`
  when this repository is hosted, e.g. on GitHub Pages).
- **Install on iPhone:** open the game in Safari → Share → **Add to Home Screen**. It then runs
  full screen with its own icon and splash screen, and works offline.
- **Move a save between devices:** Settings → Save game → **Export code** on one device, paste it
  into **Import** on the other (or download/load a save file).

## Development

```bash
cd atomcore-src
npm install
npm run dev          # local dev server
npm run build        # typecheck + production build into ../atomcore
npm test             # unit tests (engine, saves, offline, research tree) + balance bot
npm run balance      # headless bot playthrough printing progression timings
```

Browser smoke test (needs a running `npx vite preview --port 4173` and Playwright's Chromium):

```bash
PLAYWRIGHT_PATH=$(npm root -g)/playwright node tools/smoke.mjs http://localhost:4173/ tests/output
PLAYWRIGHT_PATH=$(npm root -g)/playwright node tools/smoke2.mjs http://localhost:4173/ tests/output  # offline, PWA, research, mouse placement
```

Useful URL parameters: `?quality=low|medium|high` overrides graphics quality, `?debug=1`
exposes renderer/game state on `window` for testing, `?showcase=1` opens a sandbox with every
building type (never saved).

Icons and iOS launch screens are generated by `tools/make-icons.mjs`.

## Architecture

```
src/
  game/                 pure TypeScript simulation – no React, no Three.js (runs in Node tests)
    types.ts, constants.ts, state.ts, engine.ts (tick), actions.ts (validated player actions)
    buildings/          building definitions, grid placement & collision
    simulation/         reactor model, plant energy/heat balance, modifiers
    economy/            market, prices, contracts
    research/           technology tree (50 projects, 9 categories)
    supply/             fuel cycle (mining, processing, refuelling, fuel integrity), vehicles, water balance
    events/             random management events
    progression/        levels, achievements, milestones, daily objectives, prestige, locations
  stores/               Zustand stores: game (revision counters), UI, settings
  systems/
    loop.ts             fixed-step 10 Hz simulation loop, autosave, iOS suspend catch-up
    save/               IndexedDB storage + backup, (de)serialisation & migration, cloud interface
    offline/            offline progress (runs the real engine in coarse steps, capped)
    audio/              Web Audio synthesis: ambience, effects, generative music
  components/
    buildings/          procedural model builder (merges geometry per material), materials, models
    world/              R3F scene: terrain, lighting, buildings, pipes & power lines, steam, camera
    panels/             Build, Building/Reactor, Research, Plant, Market, Goals, Sites, Settings
    ui/                 HUD, navigation, sheets, toasts, modals, icons, shared controls
  ui/                   formatting and UI action helpers
  styles/               global stylesheet (mobile-first, desktop drawer layout ≥ 900 px)
```

The simulation mutates one `GameState` object in place; the UI subscribes to a revision counter
(every tick) and the 3D scene to a structure counter (only when buildings change), so React does
little work per frame. Building models are assembled from primitives and merged into one mesh per
material, so a detailed building costs only a handful of draw calls. Graphics quality tiers
(auto/low/medium/high) control resolution, shadows, bloom, particles and vegetation, and an
adaptive monitor lowers resolution when the frame rate drops.

| Upgrades: per-building levels with downtime, condition, repairs | Implemented |
| Reactors: Pilot, SMR, PWR, BWR, Molten Salt, Fusion with output, cost, upkeep, wear, efficiency, research gates | Implemented |
| Reactor model: setpoint ramp, decay heat, temperature vs cooling, warning/trip limits, automatic setback, SCRAM & restart, fuel | Implemented (simplified, educational) |
| Neutron/fission visualisation and 3D core hologram | Implemented |
| Research tree: 50 projects across 9 categories (incl. Fuel Cycle & Mining) with prerequisites and level gates | Implemented |
| Water: evaporation from wet cooling, river/sea intakes, desert wells, treatment plants for demineralised water, storage tanks, dry cooling, droughts; shortages cut cooling or derate reactors | Implemented |
| Fuel cycle: open-pit mines with 5 excavator tiers (compact → bucket-wheel) and 4 truck tiers (dig vs haul bottleneck), ore mill, enrichment, fabrication with a QA speed/defect trade-off, inspection lab, buy/sell market for every material | Implemented |
| Fuel market limits: suppliers deliver a level-scaled number of assemblies per game day, price rises as the day sells out; Molten Salt Reactors burn enriched uranium directly; material order board (ore/yellowcake/enriched, self-produced only) paying a premium + XP; "made by / used by" explainers and market-vs-own cost card | Implemented |

| Automation: fuel procurement, outage planning (auto-refuel), auto-restart, predictive maintenance, load following, smart storage | Implemented |
| Events: heatwave, cold snap, storms, market boom/slump, demand surge, fuel price shocks, equipment failures, pump faults, breakthroughs, grants, inspections, site-specific weather | Implemented |
| Staff: capacity, salaries, understaffing penalty, training program | Implemented |
| Energy contracts with premiums, penalties, bonuses and a global tier | Implemented |
| Progression: levels, 37 achievements, 24 guided milestones, 3 daily objectives, prestige (shares), 4 unlockable sites, land expansion | Implemented |

The reactor mechanics are deliberately simplified for gameplay and education; they are not real
engineering controls or operating procedures.
