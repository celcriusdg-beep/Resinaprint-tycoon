# ATOMCORE – 3D Nuclear Power Plant Tycoon

Build, operate and grow a nuclear power company in 3D: start with a pilot reactor, research
better designs, balance heat, steam, cooling and grid capacity, sign energy contracts, expand
to four sites and eventually build a fusion plant.

- **Play:** the production build lives in [`../atomcore/`](../atomcore/) (served at `/atomcore/`
  when this repository is hosted, e.g. on GitHub Pages).
- **Install on iPhone:** open the game in Safari → Share → **Add to Home Screen**. It then runs
  full screen with its own icon and splash screen, and works offline.
- **Move a save between devices:** Settings → Save game → **Export code** on one device, paste it
  into **Import** on the other (or download/load a save file).

## Development

```bash
cd atomcore-src
npm install
npm run dev          # local dev server
npm run build        # typecheck + production build into ../atomcore
npm test             # unit tests (engine, saves, offline, research tree) + balance bot
npm run balance      # headless bot playthrough printing progression timings
```

## Architecture

```
src/
  game/                 pure TypeScript simulation – no React, no Three.js (runs in Node tests)
    types.ts, constants.ts, state.ts, engine.ts (tick), actions.ts (validated player actions)
    buildings/          building definitions, grid placement & collision
    simulation/         reactor model, plant energy/heat balance, modifiers
    economy/            market, prices, contracts
    research/           technology tree (50 projects, 9 categories)
    accidents/          incidents, emergency responses, preparedness, INES
    regulator/          permits, operating licences, inspections, findings, public opinion
    staff/              roles, hiring & training, shifts, fatigue, morale, key people
    weather/            seasons, climate, fronts, forecast, weather effects on the plant
    network/            pipes & cables: link classes, max-flow solver, auto-wiring, breakers
    supply/             fuel cycle (mining, processing, refuelling, fuel integrity), vehicles, water balance
    events/             random management events
    progression/        levels, achievements, milestones, daily objectives, prestige, locations
  stores/               Zustand stores: game (revision counters), UI, settings
  systems/
    loop.ts             fixed-step 10 Hz simulation loop, autosave, iOS suspend catch-up
    save/               IndexedDB storage + backup, (de)serialisation & migration, cloud interface
    offline/            offline progress (runs the real engine in coarse steps, capped)
    audio/              Web Audio synthesis: ambience, effects, generative music
  components/
    buildings/          procedural model builder (merges geometry per material), materials, models
    world/              R3F scene: terrain, lighting, buildings, pipes & power lines, steam, camera
    panels/             Build, Building/Reactor, Research, Plant, Market, Goals, Sites, Settings
    ui/                 HUD, navigation, sheets, toasts, modals, icons, shared controls
  ui/                   formatting and UI action helpers
  styles/               global stylesheet (mobile-first, desktop drawer layout ≥ 900 px)
```

The simulation mutates one `GameState` object in place; the UI subscribes to a revision counter
(every tick) and the 3D scene to a structure counter (only when buildings change), so React does
little work per frame. Building models are assembled from primitives and merged into one mesh per
material, so a detailed building costs only a handful of draw calls. Graphics quality tiers
(auto/low/medium/high) control resolution, shadows, bloom, particles and vegetation, and an
adaptive monitor lowers resolution when the frame rate drops.
